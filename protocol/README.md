# P0-10 offline protocol foundation (not P0-10 acceptance)

`control.proto` is the canonical POC-0 wire schema. `:protocol:generateProto` generates Java transport DTOs under `protocol/build/`; generated sources are not edited or committed. The JVM module maps ClientHello, ControlError and WatchOperationRef DTOs into domain-side models and categorized `MbResult` failures, not raw DTOs or parse exceptions. POC-0 currently accepts only protocol 1.0; schema namespace `v1` is not a product version.

## Local limits and status

- `ClientHelloCodec` rejects messages larger than 16 KiB before **parsing** an already acquired byte array. It caps app-version UTF-8 bytes at 96, capabilities at 16, and each capability at 64 UTF-8 bytes; a cheap character-count guard runs before UTF-8 sizing. No raw payload or exception text is reported.
- `withProtocolDeadline` applies a caller-chosen 1–30,000 ms coroutine deadline to **cooperative suspend work only**. It cannot preempt blocking or cancellation-insensitive operations; transport work must promptly honor scope cancellation. Timeout returns a terminal, non-retryable error without swallowing parent cancellation. Tests use virtual time. Future HTTP/WSS adapters **must** enforce the 16 KiB limit while streaming, before buffering/allocating the body; the codec alone does not provide a network allocation bound. They must choose operation-specific deadlines and propagate scope cancellation. No Ktor client, connection, signing, pairing, READY scheduling, or Watch state machine is implemented here.
- `ServerHello` bytes are **untrusted** until a future signed ServerIdentity/nonce verification boundary is in place. The Watch reference mapper requires presence of each revision field, accepts explicit zero values, and rejects uint64 values outside non-negative `Long` range; its tuple is input to future stale-operation validation, not enforcement. It does not implement Watch scheduling or stale-operation processing. Unknown error enum values are preserved by Protobuf and mapped to a typed protocol failure, never success. `ControlEnvelope` is not yet processed by a server/client.
- No two-PC, native/media or live transport evidence exists for this module. P0-07 stays stopped and P0-08/P0-09 remain blocked; the hard P0-10 dependencies and acceptance gates remain open.
