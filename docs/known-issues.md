## P0-06-LK-EXIT-001 — LiveKit startup failure exits with status zero

- **Status / severity:** Open; P1 / HIGH. Reproduced on pinned LiveKit Server `v1.13.7` during P0-06 on 2026-09-25; the bounded supervision and explicit internal Desktop proof-mode caller were independently accepted as a narrow P0-06 sidecar/lifecycle proof (OK with notes, 2026-09-25). The upstream false-success behavior remains unresolved. If it remains HIGH for a future host, do not silently downgrade this P1 risk.
- **Observed behavior:** Occupied API port and malformed YAML each produced an explicit startup error but the process exited with code `0`. The pinned `cmd/server/main.go` logs a non-nil `cmd.Run` error without returning a non-zero status. Detailed lifecycle evidence is retained locally and is not published; no machine-local path is included here.
- **Reproduction:** For the Git-visible bounded public summary and reproduction procedure, see the [native harness and runbook](../native/media-harness/README.md). Detailed proof records and raw artifacts remain local-only and are not repository links. The bounded supervisor test reproduces occupied-port and malformed-YAML exit `0`, asserts terminal failure, and checks loopback-only resource cleanup.
- **Risk:** The upstream process status remains false-success. A consumer that bypasses the project supervisor or trusts exit status may misclassify an unstarted server as successful. Media/product readiness was not tested.
- **Workaround:** `LiveKitSidecarSupervisor` requires child liveness, HTTP health, PID-owned API/UDP endpoints and loopback-only bindings; it reports typed failure and cleans its exact child/config on startup failure. `DesktopLiveKitSidecarHost` composes that same supervisor and is reachable only by explicitly launching Desktop with `--livekit-sidecar-headless`, then issuing `start <executable>` and `stop` commands. Normal GUI launch does not start LiveKit. This internal proof mode is not P0-11's `IHostedServerService` and does not implement product UI/protocol/client behavior. Independent review accepted this mitigation only as the narrow P0-06 native sidecar/lifecycle gate, not as a fix to upstream exit status. Any future host service must consume this bounded supervisor/lifecycle seam or cannot claim safe LiveKit startup. No upstream source was patched.
- **Owner:** P0-06 implementation owner; no individual assigned.
- **Target:** P0-06 is ACCEPTED NARROW on 2026-09-25 based on the independent review and retained bounded readiness/lifecycle evidence; P0-07 is IN_PROGRESS — BLOCKED-at-ICE. Any future host service must consume this safe supervisor/lifecycle seam or fail closed. The explicit headless proof-mode caller is evidence for this mitigation only; it does not close P0-11. Do not silently downgrade P1 / HIGH while that upstream risk remains high.
- **Evidence limits:** Ordinary-user Windows x64, loopback-only, pinned binary SHA-256 `a499e030f165cc15a825eb7d4afe8fc3560eaedeeb8cef3fb26e4778123cada4`. No client/media, LAN/WAN, firewall, public-port, package or graceful-signal claim. Windows CPU-capacity support remains unproven.
