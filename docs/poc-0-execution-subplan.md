## Execution rules

- Work one code slice at a time, in the dependency order below. Steps grouped in a wave are a review/coordination grouping, not permission for concurrent implementation.
- Preserve checkout changes and use the exact retained test/fixture/environment evidence for each step. Record actual commands, versions, outputs and non-sensitive artifact references; planned commands are not results.
- Do not provision dependencies/toolchains or change system state without separate user approval. Before first use, perform the step's declared bounded compatibility/license proof; a failed primary/fallback is BLOCKED pending a decision, never an implicit technology substitution.
- Keep logs/reports and runtime evidence outside Git. Never include secrets or raw runtime logs in this plan or review.
- Respect manual gates: local/synthetic tests cannot stand in for two physical PCs, WAN, a clean Windows package run or friend acceptance. Do not start POC-1 automatically after P0-27.

## Blocking/decision checkpoints

A failed Windows server contract, missing LiveKit APIs, incompatible/licensing/runtime proof, unsafe native teardown, missing required source matrix, analyser uncertainty, failed hard gate, unavailable friend/hardware/WAN or clean-machine package blocks the dependent step. Use only an already approved fallback in its stated threshold/conditions. Anything beyond those conditions requires a decision before work continues.
